# Domain Docs

This repository uses a single-context layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read ADRs in `docs/adr/` that affect the area of work when they exist.

If these files do not exist, proceed silently. The domain-modeling workflow creates them when terminology or architectural decisions are actually resolved.

## Consumer rules

- Use terms defined in `CONTEXT.md` in issue titles, proposals, hypotheses, and tests.
- If a required concept is absent, avoid silently inventing a competing term; record the gap for domain modeling.
- Surface conflicts with existing ADRs explicitly rather than silently overriding them.
